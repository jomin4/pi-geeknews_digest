# 00. 개요와 요구사항

> 상태: 확정 · 최종 수정: 2026-09-29 · 관련 ADR: [ADR-001](decisions/ADR-001-rss-source.md), [ADR-003](decisions/ADR-003-discord-text-feedback.md)

## 1. 배경

매일 18~20시에 GeekNews(news.hada.io)를 직접 열어 오늘 올라온 글 링크를 모으고, AI에 붙여넣어 요약을 받아왔다. 이 반복 작업을 자동화한다.

## 2. 목표

- 18시 전에 오늘치 GeekNews 리포트가 Discord에 도착해 있다.
- 관심 분야 글은 요약과 함께 위에, 나머지는 제목과 링크만 아래에 모여 있다.
- 피드백을 글로 남기면 다음 리포트부터 취향이 반영된다.
- 상시 서버 없이 GitHub Actions만으로 돈다. 비용은 월 몇백 원 이하.

## 3. 요구사항

| ID | 요구사항 | 관련 설계 |
|---|---|---|
| REQ-01 | GeekNews의 하루치 글을 누락 없이 수집한다 | SCH-R1~R4 |
| REQ-02 | "오늘치" 범위는 어제 17:30 초과 ~ 오늘 17:30 이하 (KST) | SCH-R2 |
| REQ-03 | 리포트는 18:00 KST 전에 Discord에 도착한다 | SCH-R5, SCH-R9 |
| REQ-04 | 관심 분야는 AI/LLM, 개발도구, 인프라/클라우드, 하드웨어 4개 | JEV-Q1 |
| REQ-05 | 관심 글 Top은 최대 8개, 요약·추천 이유와 함께 보여준다 | JEV-R4, GEM-A |
| REQ-06 | 리포트의 모든 글에 번호를 붙여 피드백에서 가리킬 수 있다 | DSC-03 |
| REQ-07 | 피드백은 Discord 피드백 채널에 자유 텍스트로 남긴다 | FB-01 |
| REQ-08 | 피드백은 다음 리포트의 판단에 반영된다 | FB-03 |
| REQ-09 | 취향 프로필은 크기를 제한하고 오래된 항목을 정리한다 | FB-05, FB-06 |
| REQ-10 | 요약은 원문에 없는 내용을 만들지 않는다 | GEM-A1, JEV-V1 |
| REQ-11 | 외부 API가 실패해도 리포트는 반드시 보낸다 | GEM-F1, DSC-07 |
| REQ-12 | API 키는 코드·데이터에 넣지 않는다 | ARCH-S1 |
| REQ-13 | 로컬에서 구현·테스트를 마친 뒤 클라우드 세션으로 옮긴다 | T00~T12 |
| REQ-14 | 테스트는 인터넷 없이도 돈다 (외부 호출은 가짜 응답으로 대체) | T00, ADR-007 |

## 4. 범위 밖

- GeekNews 개별 글 페이지 본문 읽기 (브라우저 확인 화면 때문에 불가, RSS 요약만 사용)
- 댓글 수·추천 수 반영 (RSS에 없음)
- 웹 대시보드, 주간 리포트 (나중에 검토)

## 5. 용어집

| 용어 | 뜻 |
|---|---|
| 수집 | RSS를 읽어 새 글을 수집함(articles.json)에 쌓는 일 |
| 마감 | 오늘 리포트에 넣을 글의 끝 시각. 매일 17:30 KST 고정 |
| 리포트 실행 | 17:30 실행. 최종 수집 → 피드백 해석 → 판단 → 요약 → 전송 |
| Top | 관심도가 높아 요약까지 붙는 섹션. 최대 8개 |
| 확인해볼 만한 글 | Top 기준에는 못 미치지만 관심 분야인 글 |
| 기타 목록 | 관심 분야 밖 글. 제목과 링크만 |
| 제외 | 피드백으로 빼달라고 한 주제. 리포트에 안 나오고 기록만 남음 |
| Jev | TypeSafe의 판단 모델. 글을 쓰지 않고 선택지별 확률만 돌려준다 |
| Choice / Score / Noul | Jev 질문 유형. 하나 고르기 / 등급 매기기 / 참일 확률 |
| 기준선(threshold) | 확률을 보고 섹션을 나누는 숫자. state.json에 있음 |
| 취향 프로필 | 피드백으로 쌓인 좋아요·싫어요 주제 목록 (profile.json) |
| 주간 보정 | 매주 월요일, 평가 기록을 보고 기준선 변경을 제안하는 일 |
