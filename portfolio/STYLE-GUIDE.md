# 시각화 스타일 가이드 (Excalidraw)

> 포트폴리오의 **모든 그림**은 이 규칙을 따른다. 그림은 **구조만** 보여주고, 설명은 그림 아래 본문(문제 원인 · 해결 과정 · 결과)이 한다. 면접관이 3초 안에 "무엇이 어디로 흐르고, 어디가 문제였는지"를 읽을 수 있어야 한다.

## 1. 도구와 파일

| 항목 | 규칙 |
|---|---|
| 도구 | Excalidraw |
| 원본 | `portfolio/figures/specs/FIG-*.json` (그림 명세) |
| 생성 | `python tools/figgen.py 명세.json` (또는 `--all`) → 같은 이름의 `.excalidraw` |
| 이미지 | `npm --prefix tools/portfolio run figures` → `FIG-*.svg`, `FIG-*.png`. excalidraw.com의 Export image와 같은 엔진 |
| 다듬기 (선택) | excalidraw.com에서 `.excalidraw`를 열어 손보고 같은 파일에 덮어쓴 뒤 이미지를 다시 내보낸다 |
| 파일 이름 | `FIG-{항목ID}-{짧은-영문}.{json,excalidraw,svg,png}` |

명세 형식과 만드는 순서: [figures/README.md](figures/README.md)

## 2. 뺄 것

- 그림 제목 (페이지 제목이 한다)
- 구역 박스, 범례
- 결과 수치 박스 (본문 "결과"가 한다)
- 박스 안 두 줄 설명, 긴 문장

## 3. 색 (기본은 흰색)

색은 **이 문제에서 구분해야 할 것에만** 칠한다. 한 그림에 **최대 2가지** (생성기가 넘으면 경고한다).

| 키 | 채우기 | 뜻 |
|---|---|---|
| `white` | `#ffffff` | 기본 |
| `green` | `#b2f2bb` | 해결된 부분 · 바뀐 부분 |
| `red` | `#ffc9c9` | 문제 지점 |
| `purple` | `#d0bfff` | 전체 구조도에서 구분할 역할 A (예: Jev) |
| `orange` | `#ffd8a8` | 전체 구조도에서 구분할 역할 B (예: Gemini) |

문제 해결 그림은 `red`/`green`만, 전체 구조도(FIG-P0)는 `purple`/`orange`만 쓴다.

선과 글자는 검정 `#1e1e1e`, 점선·괄호·구분선은 회색 `#868e96`.

## 4. 모양

| 키 | 모양 | 쓰는 곳 | 기본 크기 |
|---|---|---|---|
| `start` | 타원 | 흐름의 시작점 · 외부 입력 · 사람 (참고 그림의 Client) | 150×70 |
| `server` | 큰 사각형 | 중심이 되는 우리 실행 단위 (참고 그림의 Application Server) | 200×200 |
| `box` | 작은 둥근 사각형 | 저장소 · 외부 서비스 · 모델 · 단계 | 150×56 |
| `decision` | 마름모 | 꼭 필요할 때만 (대부분 화살표 라벨 `≥ 0.7`로 대신) | 140×80 |

## 5. 글자

| 어디 | 규칙 |
|---|---|
| 박스 | **이름만 한 줄** (예: `articles.json`, `Jev`, `Discord 리포트`). `server`만 두 줄 허용 (이름 + 실행 환경) |
| 화살표 번호 | `1`, `2`, `3` — 본문 "해결 과정"의 ①②③과 **같은 번호** |
| 화살표 라벨 | 번호 옆 6자 이내 (예: `하루 4회`, `≥ 0.7`) |
| 문제 주석 | 문제 지점 **한 곳**에만 빨간 글씨 10자 이내 (예: `최신 50건만`) |
| 묶음 | 구역 박스 대신 괄호 선 + 한 단어 (예: `git`) |
| 행 이름 | 두 줄 그림의 왼쪽에 회색 한 단어 (예: `개선 전`, `매일`) |

글꼴은 Excalidraw의 일반 글꼴(Normal), 크기 16(박스) · 15(화살표·주석). 한글은 보는 기기의 기본 글꼴로 나온다.

## 6. 선과 배치

- 선은 깔끔한 직선 (손그림 효과 없음), 굵기 1.
- 실선 = 같은 실행 안의 흐름, 회색 점선 = 다음 실행으로 넘어가는 흐름.
- 흐름은 **왼쪽 → 오른쪽**, 최대 두 줄. 박스 4~7개.
- 화살표 사이 간격은 최소 90px (번호·라벨이 들어갈 자리).
- 가로로 넓게: PDF에서 본문 폭 전체, 높이 40~75mm.

## 7. 그림 유형

| 유형 | 쓰는 곳 | 구성 |
|---|---|---|
| 구조 + 문제 지점 (기본) | 대부분의 문제 해결 항목 | 해결 후 구조 한 장. 바뀐 부분은 초록, 문제가 생기던 지점에 빨간 주석 |
| 개선 전후 | 전후 비교가 핵심일 때 (예: P2 호출 수) | 같은 흐름을 위아래 두 줄로, 왼쪽에 `개선 전`/`개선 후`, 사이에 회색 점선 |
| 전체 구조 | 프로젝트 요약 쪽 | 중심 `server` 박스와 주변 서비스. 번호 없이 짧은 라벨만 |

## 8. 확인 목록 (그림을 만든 뒤)

- [ ] 박스 글자가 한 줄인가 (server 제외)
- [ ] 색이 2가지 이하이고 뜻이 표 3과 맞는가
- [ ] 번호가 본문 해결 과정 번호와 같은가
- [ ] 빨간 주석이 한 곳뿐인가
- [ ] 글자가 선이나 박스와 겹치지 않는가 (PNG를 열어 확인)
- [ ] 측정하지 않은 숫자가 그림에 없는가
