# R2. GitHub Actions 예약 실행 지연 속에서 18시 전 리포트 도착 보장 (예비, 가제)

> 상태: 예비 · 관련 설계: SCH-R3, SCH-R5, ADR-004 · 그림: 미작성 (`RESULT` 유형 예정) · 증거: `evidence/R2/`

## 배경 (설계 단계에서 확인한 사실)
- GitHub Actions의 예약 실행은 서버가 붐비면 늦게 시작될 수 있다.
- 처음 설계는 17:50 마감이었지만, 지연을 고려해 17:30 시작·고정 마감으로 바꿨다 (ADR-004).

## 측정 계획
| 지표 | 방법 | 조건 |
|---|---|---|
| 시작 지연 분포 | 예약 시각 대비 실제 시작 시각 (`metrics.jsonl`의 `scheduled_at`, `started_at`) | 14일, 네 가지 실행 모두 |
| 18시 전 도착률 | Discord 메시지 1 전송 시각이 18:00 이전인 날의 비율 | 14일 |
| 17:50 시작이었다면 | 관측한 지연 분포를 17:50에 더해 계산한 모의 도착률 | 같은 데이터 |

## 승격 조건
지연이 실제로 수 분 이상 관측되면 P 항목으로 올린다.
