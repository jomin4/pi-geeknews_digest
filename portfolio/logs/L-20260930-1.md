# L-20260930-1 17:30 전·자정 넘어 시작한 리포트 실행의 마감이 문서에 없었음

- 날짜: 2026-09-30
- 작업: T02 · 환경: 클라우드 세션
- 관련 설계 ID: SCH-R3, SCH-R6, SCH-R8, SCH-R9
- 연결 후보: P1 (범위 경계), R2 (예약 실행 지연)
- 기록: Claude Code

## 상황
T02에서 "오늘 마감"을 계산하는 `report_cutoff(now)`를 만들던 중, 실행이 17:30 전에 시작하는 경우를 문서에서 찾지 못했다.

## 현상
문서 원문 (docs/02-schedule-and-range.md, 수정 전):
```
| SCH-R3 | 마감 시각은 실제 실행 시각이 아니라 **17:30 KST로 고정**한다. 실행이 17:50에 시작돼도 마감은 17:30이고, 17:30~17:50 글은 내일 리포트로 간다 |
```
"오늘 날짜의 17:30"으로 읽으면, 10:00 수동 실행(workflow_dispatch, `--cutoff` 없음)의 마감이 아직 오지 않은 오늘 17:30이 된다. 전송이 성공하면 SCH-R6에 따라 `last_cutoff`가 오늘 17:30으로 옮겨지고, 10:00~17:30에 올라올 글은 `published > last_cutoff`(SCH-R4)를 통과하지 못해 어느 리포트에도 들어가지 않는다. 예약 실행이 자정을 넘겨 시작하는 경우도 같은 문제가 생긴다 (다음 날 17:30이 마감이 됨).

## 원인
SCH-R3이 17:30 이후 시작(지연)만 예로 들고, 17:30 전·자정 이후 시작을 정하지 않았다. 코드를 쓰기 전에 문서를 다시 읽어 확인했다.

## 시도
| # | 시도한 방법 | 결과 |
|---|---|---|
| 1 | 사용자에게 두 가지 해석(가장 최근 17:30 / 항상 오늘 17:30)과 누락 위험을 제시 | 사용자가 "가장 최근 17:30" 선택 |

## 선택과 이유
마감 = 실행 시각 이전의 가장 최근 17:30. 아직 오지 않은 시각을 마감으로 잡지 않으므로 누락이 생기지 않고, 이미 보낸 마감이면 SCH-R9로 건너뛴다. SCH-R3 문구와 "마감 시각 사례" 표를 02 문서에 추가했다.
